# 从底座继续扩展

## 代码分工

| 文件 | 职责 |
| --- | --- |
| `src/schema.ts` | Agent、模型、外观的输入与类型契约 |
| `src/storage.ts` | 公共模板 + 本机覆盖、环境密钥、原子落盘、技能读取范围 |
| `src/providers.ts` | 协议转换与单次 HTTP 请求，不重试、不回显原始错误 |
| `src/engine.ts` | 会话隔离、配置快照、回合循环、取消与持久化回执 |
| `src/server.ts` | 身份、同源、防跨站、接口与受控静态文件 |
| `src/lock.ts` | 同一数据目录只允许一个后端进程 |
| `web/` | 无框架界面；所有聊天文本走 textContent |

UI 发出消息后立即得到运行 ID，随后只读查询进度。模型运行不绑定浏览器连接。不要把页面轮询失败当成再次发模型请求的理由。请求 ID 复用同一回执；内容不同却复用 ID 会拒绝。

模型回合中，技能目录只包含当前 Agent 白名单；`read_skill` 的范围在后端再次检查。技能的说明与正文只是文本，不拥有“忽略前面限制”的权限。

## 新的模型后端

在 `ModelSchema` 增加显式协议，再扩展 `Complete` 适配。不把某个后端偷偷变成其他模型的 fallback。对本机模拟 HTTP 服务测试正常回答、工具调用、格式错误、401 / 429 / 5xx、取消和超时；测试里不用真实 Key。

把 Key 留在环境中，前端只显示 `hasKey`。避免 URL 查询参数认证，防止 Key 混入日志。服务商响应不能直接原样回传给界面；它可能包含内部信息。

## 新的工具

当前仅实现 `read_skill`，不提供任意代码执行。新增工具至少需要：

1. 明确参数 schema 和服务端工具白名单。
2. 路径、网络、身份和本次授权检查。
3. 写操作的确认、幂等键和结果不明时停止重放。
4. 超时、取消、最大结果体积和可解释的 Trace。
5. 独立测试，包括模型伪造工具名/路径及恶意资源内容。

不要直接把任意函数、文件路径、MCP 服务或子进程暴露给模型。外部工具即使可读，也可能传走用户内容，需要明确说明。

## 扩展与公开版本分开

私人 Agent 和 Skill 放 `data/`。自定义业务流程、真实服务配置、私有素材不应直接复制进公共模板。要发布通用能力时，重新制作中性示例，检查第三方许可，并经过公开文件审计。

底座不内置业务 Workflow 执行器。若后续需要，可独立设计声明式流程模块；先定义权限、幂等、预算、断点与恢复语义，不用“重新运行全部步骤”代替未知副作用处理。
